## PASSO 1 — SEGREDO SOLTO

CACA ARQUIVO QUE NUNCA DEVE ENTRAR NA PILHA:

```sh
git ls-files | grep -Ei '\.(key|pem|p12|pfx|jks|crt)$|(^|/)\.env'
```

| CHEIRO | O QUE E |
| --- | --- |
| `.env` `.env.*` | SENHA E CHAVE DO AMBIENTE |
| `*.key` `*.pem` | CHAVE PRIVADA. PORTA DA CAVERNA. |
| `*.p12` `*.pfx` `*.jks` | MOLHO DE CHAVE FECHADO |
| `id_rsa` `*.ppk` | CHAVE DE ENTRAR EM OUTRA MAQUINA |
| `*.sqlite` `*.dump` | BANCO COM DADO DE GENTE DE VERDADE |

ACHOU ALGUM NA LISTA DO `git ls-files`? **CRITICAL.** VAI PRO PASSO 5 AGORA.

## PASSO 2 — SEGREDO ESCRITO NO MEIO DO CODIGO

```sh
grep -rEin 'api[_-]?key|secret|passwd|password|token|BEGIN [A-Z ]*PRIVATE KEY' \
  --exclude-dir=.git --exclude-dir=node_modules .
```

- ACHOU VALOR DE VERDADE? **CRITICAL.**
- ACHOU SO NOME DE VARIAVEL VAZIA (`API_KEY=`)? TA BOM. SEGUE.
- ACHOU SENHA DE EXEMPLO TIPO `troca-isso`? **INFO.** MAS DEIXA CLARO QUE E EXEMPLO.
- ACHOU SO `RecurrentTasks/ChecarSeguranca.md`? E ESSA RECEITA MORDENDO O PROPRIO RABO:
  AS PALAVRA MORAM DENTRO DELA. NAO E FURO. SEGUE.

## PASSO 3 — `.gitignore` TAPA O BURACO?

```sh
for f in .env .env.local chave.key certo.pem; do
  printf '%s -> ' "$f"; git check-ignore -q "$f" && echo IGNORADO || echo EXPOSTO
done
```

- DEU `EXPOSTO`? ARRUMA O `.gitignore` AGORA. **HIGH.**
- `.gitignore` VAZIO NUM PROJETO QUE JA TEM CODIGO? **HIGH.**
- LEMBRA: `.gitignore` SO SEGURA ARQUIVO QUE AINDA NAO ENTROU.
  JA ENTROU UMA VEZ? ENTAO NAO E SO ARRUMAR O `.gitignore`. VAI PRO PASSO 5.
